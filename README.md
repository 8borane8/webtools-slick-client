## ✨ Features

- Lightweight client-side library
- Seamless Single Page Application (SPA) navigation: the latest click wins, scroll is restored on back/forward, and a
  loading state is exposed
- `parseForm` / `encodeBody`: read a form and send it in a shape [`expressapi`](https://jsr.io/@webtools/expressapi)
  validates as is
- Utility class for easy cookie management

## 📦 Installation

```bash
deno add jsr:@webtools/slick-client
```

## 🔗 Usage with slick-server

With [`slick-server`](https://jsr.io/@webtools/slick-server) 0.7.1 or later, `client: true` bundles Slick Client from
the version declared in **your project's** `deno.json`. The server renders the HTML, initializes the client with the
current template and answers navigation requests with JSON.

```json
{
	"imports": {
		"@webtools/slick-client": "jsr:@webtools/slick-client@^0.4.0"
	}
}
```

That version is the one that runs in the browser, through the import map generated by the server, and the one your own
scripts and islands import `Cookies`, `parseForm` or `FormHandler` from.

Slick Client relies on the markup produced by `slick-server`:

- a `<div id="root">` holding the template,
- an element with `id="app"` inside the template, where the page is rendered,
- a `<title>` and a `<link rel="shortcut icon">` in the `<head>`,
- `slick-type="template"` / `slick-type="page"` attributes on the styles and scripts, to swap them between pages.

## 🧠 Slick Class

- **redirect(url, options?)**: navigates client-side.
- **addOnloadListener(fn)**: runs `fn` after each navigation, returns a function that removes the listener.

### Automatic DOM Handling

Slick intercepts links and `GET` forms with two listeners on `document`, so content added later is handled too.

#### Links (`<a>` tags)

- Clicking a same-origin link triggers a client-side navigation.
- The browser keeps handling links with a `target` other than `_self`, `download` links, cross-origin links
  (`https://…`, `mailto:`…), links with `data-slick-ignore`, and clicks with Ctrl, Cmd, Shift, Alt or the middle button.
- If only the hash changes, nothing is fetched: Slick scrolls to the element (smoothly unless the user prefers reduced
  motion).
- `data-slick-reload` forces the template to be fetched again, even on the current page.

```html
<!-- Client-side navigation -->
<a href="/about">About</a>

<!-- Same page, different section: scroll only, no fetch -->
<a href="/docs#installation">Installation</a>

<!-- Fetch the current page again (replaces the history entry) -->
<a href="/dashboard" data-slick-reload>Refresh</a>

<!-- Left to the browser -->
<a href="/report.pdf" download>Report</a>
<a href="/logout" data-slick-ignore>Log out</a>
<a href="/external" target="_blank">External</a>
<a href="https://example.com">External Site</a>
```

#### Forms with `GET` method

A form without a `method` attribute is a `GET` form, like in the browser. Its fields (and the submit button that was
used, `formaction` and `formmethod` included) become the query string of the target URL.

```html
<form action="/search">
	<input type="text" name="q" />
	<button type="submit">Search</button>
</form>
<!-- Submitting navigates to /search?q=… -->
```

#### Forms with `POST` method

`POST` forms are not handled: submitting one is a full page load. To submit data and stay in the SPA, use `parseForm`
(or `FormHandler`) and send the request yourself.

### Manual navigation

```ts
import { Slick } from "@webtools/slick-client";

await Slick.redirect("/about");

// Options
await Slick.redirect("/page", {
	reload: true, // fetch the template again
	scroll: false, // leave the scroll position alone
	replace: true, // replace the history entry instead of adding one
});

// Same page, different hash: scroll only, no fetch
await Slick.redirect("/docs#section-2");
```

**The latest navigation wins**: starting one cancels the previous request, so a quick second click is never ignored. A
request that fails, times out (30 s) or does not answer with the expected JSON falls back to a full page load.

### Loading state and events

```css
/* <html data-slick-loading> while a navigation is in progress */
html[data-slick-loading] body {
	cursor: progress;
}
```

```ts
// After each navigation (the page is rendered and its scripts have run)
document.addEventListener("slick:navigate", (event) => {
	console.log((event as CustomEvent).detail.url);
});

const remove = Slick.addOnloadListener(() => {
	console.log("Page loaded!");
});
remove();
```

`addOnloadListener` is not called for the first page load, only for navigations. Page scripts are executed again on
every visit of their page, so a listener registered in one must be removed (keep the function returned by
`addOnloadListener`) or it is registered once more at each visit.

An error thrown by a listener is logged and does not stop the navigation.

### Accessibility and scroll

- After a navigation, the focus is moved to `#app` (`tabindex="-1"`) unless the URL targets an element with its hash.
  Add `#app:focus { outline: none; }` if you do not want a focus ring.
- The scroll position is saved in the history entry and restored on back/forward and reload.

### Limits

- `<script>` tags written in a `head` or a `body` are inserted with `innerHTML` and do not run. Use the `scripts` of the
  template or page.
- Scripts are loaded again at each visit (a `cacheBust` query is added so the module runs again).

## 🍪 Cookies Class

Values are read and written as they are, like in `expressapi` (`req.cookies`, `res.cookie`).

- **get(cname)**: the value of a cookie, or `null`.
- **set(cname, cvalue, days = 365)**: sets a cookie (`Path=/; SameSite=Lax`, `Secure` on https). Throws if the name or
  the value contains a space, `;`, `,`, `"` or `\`, or if the name contains `=`.
- **delete(cname)**: deletes a cookie.

```ts
import { Cookies } from "@webtools/slick-client";

Cookies.set("username", "john_doe");
Cookies.get("username"); // "john_doe"
Cookies.delete("username");
```

## 📝 Forms

### `parseForm(form)`

Reads a form into an object a server schema can validate as is. It is a plain function: use it from a page script or
from an island, with uncontrolled fields.

| Field                                                           | Result                                                                                          |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| text, textarea, select, email (lowercased), password, hidden…   | `string`                                                                                        |
| `type="number"`, `type="range"`                                 | `number`, left out when empty                                                                   |
| `inputmode="numeric"` / `"decimal"`                             | `number`, left out when empty; text that is not a number is kept as is so the server refuses it |
| checkbox                                                        | `boolean`                                                                                       |
| several checkboxes with the same `name`                         | `string[]` of the checked values                                                                |
| radio                                                           | the checked value, left out when none is checked                                                |
| `select multiple`                                               | `string[]`                                                                                      |
| file                                                            | `File`, or `File[]` with `multiple`; left out when empty                                        |
| `data-transform="csv"`                                          | `string[]` (`"a, b,, c"` gives `["a", "b", "c"]`)                                               |
| `data-transform="json"`                                         | the parsed value, left out when the JSON is invalid                                             |
| disabled fields, `submit` / `button` / `image` / `reset` inputs | ignored                                                                                         |

Empty values are **left out** rather than `null`, which is what `z.optional` expects (and a `null` in a multipart body
would turn into the text `"null"`). Empty text fields stay `""`.

`parseForm` does not clean what the user types: use native attributes (`type="number"`, `min`, `max`, `pattern`) and let
the server validate.

### `encodeBody(body)`

Encodes a body the way `HttpClient` of `expressapi` does, to spread into `fetch`: JSON, or multipart as soon as a file
is present (objects and arrays are then sent as JSON strings, which `expressapi` schemas parse back). `undefined` values
are left out.

```ts
const response = await fetch("/users", {
	method: "POST",
	...encodeBody(parseForm(form)),
});
```

### `FormHandler`

`FormHandler` calls your handler on submit with the parsed body and the submit button that was used. While the handler
runs, the form has `aria-busy="true"`, the button is disabled, and a second submit is ignored.

```ts
import { encodeBody, FormHandler } from "@webtools/slick-client";

new FormHandler(document.querySelector("form")!, async (body, submitter) => {
	const response = await fetch("/users", { method: "POST", ...encodeBody(body) });
	if (response.ok) await Slick.redirect("/users");
});
```

### End to end with expressapi

```html
<form id="signup">
	<input name="username" required />
	<input type="email" name="email" required />
	<input type="number" name="age" min="0" />
	<input type="checkbox" name="newsletter" />
	<input type="file" name="avatar" />
	<button type="submit">Sign up</button>
</form>
```

```ts
// client
import { encodeBody, FormHandler, Slick } from "@webtools/slick-client";

new FormHandler(document.querySelector<HTMLFormElement>("#signup")!, async (body) => {
	const response = await fetch("/signup", { method: "POST", ...encodeBody(body) });
	if (response.ok) await Slick.redirect("/welcome");
});
```

```ts
// server (expressapi)
const server = new HttpServer().addRoute({
	url: "/signup",
	method: "POST",
	schemas: {
		body: z.object({
			username: z.string().min(1),
			email: z.string().email(),
			age: z.optional(z.number().int()),
			newsletter: z.boolean(),
			avatar: z.optional(z.file().maxSize(2_000_000)),
		}),
	},
	requestListener: (req, res) => res.json({ success: true, username: req.body.username }),
});
```

The same applies to the `onpost` of a `slick-server` page. To type the body, give `FormHandler` the type of your schema:
`new FormHandler<InferSchemaType<typeof schema>>(…)`. With the typed `HttpClient` of `expressapi`, pass
`parseForm(form)` as the `body` and skip `encodeBody`.

From an island:

```tsx
export default function Signup() {
	return (
		<form
			onSubmit={(e) => {
				e.preventDefault();
				fetch("/signup", { method: "POST", ...encodeBody(parseForm(e.currentTarget)) });
			}}
		>
			<input name="username" />
			<button type="submit">Sign up</button>
		</form>
	);
}
```

Two limits of `expressapi` to keep in mind: several files sent under the same key keep only the last one, and a `400`
validation answer does not tell which fields were refused.

## ⬆️ Upgrading from 0.3

- With `slick-server`, bump `@webtools/slick-client` to `^0.4.0` in your `deno.json`. The `Slick.initialize(name, true)`
  call written by the server of that era still works: the extra argument is ignored.
- `Slick.initialize(template, newVersion)` is now `Slick.initialize(template)`. The old request format is gone.
- `Slick.redirect(url, reload, goTop, fromHistory)` is now `Slick.redirect(url, { reload, scroll, replace })`.
- `Slick.addOnloadListener` returns a function that removes the listener.
- `FormHandler` no longer cleans numeric and email inputs while the user types, and its handler receives the submit
  button as `HTMLElement | null`. Use `parseForm` to read a form anywhere.
- Empty numbers, unchecked radios and missing files are left out of the body instead of being `null`.
- `Cookies.set` throws on forbidden characters, and does not set `Secure` on plain http.
